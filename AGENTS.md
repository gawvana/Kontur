# Контур: инструкции работы с репозиторием

## Назначение
Telegram Mini App + бот, API, admin и background jobs. Полная задача исправления: docs/CODEX_FULL_REPAIR_PROMPT.md. Актуальный независимый baseline: docs/NEW_VERSION_INDEPENDENT_AUDIT.md. Старые STATUS/REQUIREMENTS_MATRIX не являются доказательством реализации.

## Порядок работы
Сначала git status, структура проекта, manifests/lockfiles, миграции и аудит. Определи фактические команды установки и запуска по manifests. Работай в отдельной ветке, сохраняй чужие изменения. Веди docs/WORKLOG.md и матрицу закрытия N01–N32. Действуй автономно в пределах задания; не спрашивай разрешение на обычные обратимые правки и тесты.

## Инварианты
Сохраняй Telegram HMAC auth, обязательный JWT secret, session revoke и object ACL. Staff 2FA проверяется на текущей сессии. Черновики и оригиналы приватны. Только одобренная версия публична. Appeals реально изменяют эффекты решения и reputation. Mock scanner/delivery запрещены в production. SavedContact без Subject — допустимая приватная запись. Username не равен постоянной identity.

## Проверки
Используй отдельные тестовые БД/storage/бота. Не удаляй пользовательские данные и не исправляй миграции reset базы. SQLite и offline SQL generation не подтверждают PostgreSQL. Проверяй API/UI DTO реальными browser/integration сценариями. Не ослабляй тесты ради зелёного результата. Secrets не печатать и не коммитить. Деплой только в назначенные системы при наличии авторизации, без автоматических покупок.

## Статус
Это непочиненный audit baseline. Зависимости не включены; их установка должна использовать lock/manifests. Документируй фактические commands и external blockers. Полная готовность требует выполненного процесса от интерфейса/бота до DB/storage/jobs и безопасных побочных эффектов.
